# توزيع الكود في المراحل الجاية

المرحلة 0 فيها شاشة تجربة واحدة فقط. التقسيم ده هيتطبق مع إضافة أول خصائص فعلية؛ مش هنحط مجلدات فاضية بدل تنفيذ حقيقي.

| المسار | مسؤوليته |
|---|---|
| lib/core/ | الألوان والخطوط، الصوت، التخزين، قواعد الوقت، معرّفات المحتوى |
| lib/features/onboarding/ | اسم الطفل وصورته، أول تشغيل |
| lib/features/world_map/ | الجزر وترتيب الفتح |
| lib/features/unit_01/ إلى unit_09/ | رحلة كل وحدة وربط مشاهدها |
| lib/games/ | مشاهد Flame، التفاعل والسحب والمطابقة المشتركة |
| lib/content/ | قراءة JSON والتحقق منه وقواعد تقييم قرارات اللعب |
| lib/parent/ | البوابة وتقارير الوحدات والإعدادات |
| lib/l10n/ | نصوص الواجهة الإنجليزية والعربية واتجاه العرض |
| assets/content/ | المصدر وإصدارات المحتوى القابل للعب بعد المراجعة |

Riverpod هيربط حالة التطبيق بالخدمات في المرحلة 1. منطق تصحيح القرارات والتقدم هيبقى منفصل عن الرسم والصوت وقابل للاختبار. مشهد اللعبة يرسل الحدث ومعرّف العنصر؛ المحرك يرجع نتيجة المحاولة والتلميح المناسب، والتقرير المحلي يتحدّث مرة واحدة للحدث.

الواجهة تتعامل مع حجم المساحة المتاح، مش اسم الجهاز. الأزرار 64dp على الأقل والنصوص قابلة للتكبير. المناطق العربية اتجاهها RTL من البداية. الألعاب أفقية، مع استيعاب قرارات نظام التابلت بخصوص تدوير الشاشة.
