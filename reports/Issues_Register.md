## Recommendations (not defects)

| ID | Recommendation | Severity | Why |
|---|---|---|---|
| REC-01 | Get a privacy and legal decision **before** building accounts and sync | HIGH | The product decision says *"no accounts and no data sending"* (`docs/PRODUCT_DECISIONS.md`). Syncing children's data to a server brings in children's privacy law (e.g. COPPA, GDPR-K, and local law). Accounts should belong to the **parent**. Children should remain profiles with no credentials. |
| REC-02 | Make the app offline-first, with accounts optional | HIGH | The game's value today is that it works offline with zero permissions. Sync should be an add-on and must not be required to play. |
| REC-03 | Do not sync child photos by default | MEDIUM | Photos are the most sensitive data. Keep them on the device, or sync them only on explicit opt-in, encrypted, with short-lived signed URLs. |
| REC-04 | Produce a release build (AAB, R8, `--obfuscate --split-debug-info`) and test it on a physical device | MEDIUM | Only debug APKs have ever been produced, and the README says device testing is still pending. |
| REC-05 | Generate the API client from OpenAPI (Dart) | MEDIUM | This keeps the Android, Web and backend contracts in step (see the future architecture). |
| REC-06 | Add a CI gate for content validation (`scripts/validate_playable.py`) | LOW | The validators exist but run only by hand, on a machine that currently has no Python on its PATH. |
